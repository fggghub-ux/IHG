# 恢复说明与核验范围

## 代码来源

唯一的新版代码来源为用户上传的 u2phone 1.0.5 APK 的 `assets/public/`。Phone- 旧仓库当前提交 `bbf167cbee073c52104928f698f7baed811319f3` 的 108 个文件与上传的旧源码压缩包按 Git blob 哈希全部一致。

更新日志用于核对模块范围，未用日志猜写功能，未将旧版业务代码覆盖到新版。版本日期依据用户提供的信息和页面内版本标记，不能用 APK 本身证明一份完整的更新历史。

## 实际恢复内容

- APK 内 149 个前端文件中保留 143 个：88 个 JavaScript、HTML/CSS、图片字体及模板等。
- 解开 121,203 处字符串查表调用，删除对应的查表函数、数组轮转和无用别名。
- 简化常量数字和布尔表达式，将可还原的属性访问整理成常规写法。
- 主聊天文件进一步替换 1,275 处辅助调用、851 处辅助常量引用，移除 31 个辅助对象，还原 3 处打乱的执行顺序。
- 对逻辑运算包装保留“两个参数都先求值”的 APK 行为，没有直接替换成可能跳过第二参数的短路写法。
- 结合旧源码结构片段和当前代码的公开 API 名称辅助重命名。部分变量仍为中性名称；这些名称是重建结果，不能声称全部为原名。
- 各 App 保留最新版实际的文件边界，Cphone 与 Loves 独立保留；新 App 沿用 `js/<app>.js`、`css/<app>.css` 的风格。
- HTML、CSS、图片、字体及 HTML 模板内容按 APK 字节保留。入口的加载顺序、版本参数和原有配置不变。

## 未混入的内容

未加入 AndroidManifest.xml、DEX、resources.arsc、Android res/META-INF 等原生编译或签名产物。未混入旧源码中 APK 已不存在的业务文件。

排除以下 6 个前端目录中的非活动文件：

- `cordova.js`、`cordova_plugins.js`：均为 0 字节，入口未引用。
- `css/call.css.backup`、`js/call.js.backup`、`js/imessage/4_chat_list.js.backup`：备份文件。
- `js/call_optimizations_patch.txt`：历史补丁说明。

`assets/vendor/fontawesome/`、`js/vendor/mcp_client_sdk.js`、`js/vendor/native_bridge.js` 是前端实际依赖，保留在各自 vendor 位置，避免删除后出现图标或功能缺失。

## 已完成的核验

1. 88 个业务及依赖 JavaScript 文件均可解析，入口本地脚本/样式引用均存在。
2. 第一轮反混淆后的重命名，以及第二轮辅助结构处理后的名称整理，各完成 88 个文件的作用域绑定 AST 比对。此项检查名称整理是否改变变量引用关系；不等于所有反混淆变换已获得数学意义上的完整行为证明。
3. 在隔离浏览器中分别加载 APK 原始前端与重建前端，使用相同视口、相同随机种子，阻止外部网络请求。两者的 2,612 个 DOM ID、页面可见文字、118 个相关公开全局项、imApp/imChat/imDataUtils 等公开接口列表、登录/注册切换均一致；本地资源 404 均为零。
4. 两份页面均出现同一条沙箱 iframe 的 serviceWorker SecurityError；未发现重建版新增的该类异常。测试中明确阻止了 Service Worker 与外部请求，因此这不代表通知或联网服务已通过验证。

## 尚未验证或无法恢复

没有使用真实账号完成所有 App 的端到端操作，没有验证真实 AI 请求、登录后数据、音乐登录、远端 MCP 服务或 Android 插件。这份包的“可启动与结构核验通过”不能解释成全部功能均已实测通过。

无法找回打包前全部原始注释、全部变量名、原 Git 历史、签名密钥及完整 Android 构建工程。新增的 `package.json` 和 `tools/` 只负责启动、检查这份前端，替代旧包中指向缺失构建工具的配置；它们不是原构建脚本的还原。

各文件的 APK 路径、旧版是否存在、输入输出哈希及处理计数见 `source-manifest.json`。
